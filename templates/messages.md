# 派单、回执和消息模板

由 Bot 按需填写，适用字段才展开。普通交流保持自然语言。

## 派单

```text
项目 / 节点 / 接收方：
目标、原要求编号和来源：
输入材料与有效成果：
原生会话、主机和工作区：
允许动作、写入范围和实际投入边界：
产物、完成条件和验收方法：
依赖、共享资源、集成人：
下一检查点和完成通知方式：
```

复用准确的材料指针，避免转发整段历史。来源不明的次数、预算和限制不能说成用户规定。

## 工程师回执

```text
项目 / 节点：
实际执行身份与本回合证据：
做了什么，产物位置与版本：
检查结果，哪些没有检查：
缺口 / 偏差 / 假设：
下一步及需要交接的控制权：
实际用量及口径，缺失项和原因：
```

发送方持续负责交接，直到接收方取得必要信息和控制权；进度记账不阻塞已授权的独立工作。

## 三类主动通知

**【要你定】** 项目与具体决定；推荐和理由；选项的成本、风险、可回退性；证据属于实测、推断还是假设；改变推荐的条件。可用 A/B 方便简答，也接受自然语言。用户未答时，依赖这个答案的动作保持待定。

**【已交付】** 本轮完成范围；打开哪里；原要求逐项结果；实际检查与版本；偏差；未确认假设；剩余限制。下一步只是候选时明确说明。

**【仅告知】** 有意义的变化、影响、已采取行动与下一步。无变化的常规核对不发通知。

推荐项不是自动批准的默认项。已授权的日常选择不应再次包装成必须用户回答的问题。

## 用户直接找工程师

查询：给已有证据的范围、版本和时间；过期或矛盾时核查后回到原聊天答复。

改要求：保留原话、变化影响和仍有效要求，发给负责人及进度维护者；涉及控制权冲突时完成交接。用户不需要再复述一次。
