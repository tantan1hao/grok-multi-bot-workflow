# 按任务选择验收

检查写清输入、环境、步骤、预期结果、输出、产物版本与未覆盖范围。按目标选择清单，不把整库强加给每件小事。

## 检查本身是否有效

关键缺陷检查优先复现改动前版本的失败，也可用已知错误样本或隔离、可回退的故障。记录是否抓住预期错误，不故意损坏在用工程或真实数据。没有合适负例时说明证据边界，不伪造失败。

编号、版本、文件和退出结果用工具机械比对，语义正确性仍需检查。

## 缺陷与小修改

原问题和复现 → 影响范围 → 改前或已知坏样本 → 改后同一检查 → 必要邻近回归 → 实际入口。轻微文字修改检查呈现和链接即可，不强制两人评审或完整回归。

## 重构与兼容性

保留可运行基线和相同输入，说明必须兼容的行为。核对接口、错误、状态转换、默认入口与共享状态。

出现差异时排除环境、权限、资源、时序与随机条件不同，区分必须兼容、允许扩展与待决定差异。不能删能力、过滤失败或重定义要求来让比较通过。

## 性能与资源

按目标选冷启动、端到端与工具延迟、常驻和峰值内存、CPU、成功吞吐、错误率及并发条件，注明未选理由。

记录基线和候选版本、硬件、配置、输入规模、模型与网络外因、预热、采样方法和噪声。重复次数服务于具体目的，不把固定三次当通用充分证明；样本不足时不强报尾延迟。避免同机争用污染对比。

阈值来自原要求或有依据的方案，未定时先报告测量，不伪造“达标”。

## 界面与真实入口

写出从哪里开始、操作顺序、输入、预期结果和交付位置，保留必要输出。截图存在不代表整条流程成功，替代入口通过不代表默认入口可用。

## 长任务与中断恢复

按目标选停止与恢复、重复请求、资源增长、依赖失效、完成事件丢失等场景，说明时长、负载和检查点依据。恢复前后核对任务身份、输入与成果。

模拟事件只证明相应处理，单次短跑不能宣称长期无人值守稳定。

## 文档、报告与数据

核对原要求、来源、数据截止日、计算、缺口、可读性、附件与入口。格式完整不代表内容充分；数字正确、匿名化完成、表达效果与提示词普遍优劣是不同结论。

## 技术争议

核对各方原始证据与假设，再做有时间和投入边界、可回退的小试验，预先写好选择条件、灰区与停止条件。方法见 [成本与技术决策](cost-and-decisions.md)。
