# 验证范围与方法

本仓库是从实际部署整理出的通用文档。原部署的个人设定、内部项目材料和原生日志不随仓库发布。

## 当前状态

- 机制覆盖自然需求、多项目、三类工程师、并行、接续、独立验收和交付。
- 配置保存回读和部分角色文件可达性曾在具体环境中检查，不证明公开版在其他环境已经生效。
- 本公开版尚无可公开复核的独立真实任务全流程验收结果，也没有长期无人值守或普遍节省成本的结论。
- 发布前检查内部链接、模板一致性与公开内容边界；静态检查不等于行为验收。

## 分开记录四个层次

| 层次 | 证据 |
| --- | --- |
| 配置保存 | 实际角色保存与重新读取的原文、身份、版本 |
| 文件可达与加载 | 各角色通过自身入口读取相应正文的工具结果 |
| 辅助执行 | 逐步指导下的真实操作、失败、产物和验收 |
| 自然任务行为 | 只给目标与边界，Bot 自主选择拆分/工具/接续并交付 |

长期效果需要跨任务、跨时间的证据，一次成功不能跳过中间层次。

## 有意义的检查

- 模糊需求能否保留原话、调查动机并约束假设。
- 要求遗漏能否被编号比对和语义检查发现。
- 并行是否产出有用结果，减少等待而不增加冲突。
- 完成事件是否送达，漏接时的补查是否实际可用。
- 新上下文能否凭材料恢复现状；无法隔离旧上下文时只称材料恢复检查，不称冷启动测试。
- 用户直接改要求、暂停或在原生工具操作后，控制权与记录是否一致。
- 验收是否抓住隔离的已知错误，是否检查最终用户入口。

验证避开正在运行的任务和不可回退环境。记录失败、纠正和未测项，不挑成功案例冒充全量结果。

## 观察指标

状态不符比例；原要求回应率与满足率；“说通过但用不了”的次数；可避免的阶段等待；复核发现、漏检和后续故障；用户纠正次数；首次合格交付时间与总投入。

写明样本量、任务类型和口径。复核长期零发现值得调查，但不能单凭此断言无效；模型家族不同也不是独立性充分证据。

公开案例只提交获授权且脱敏的材料，保留可复现条件与证据边界。见 [贡献说明](../CONTRIBUTING.md)。
