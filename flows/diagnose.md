# 停滞与失败诊断

触发：错误、重复失败、检查点到期、事件失联或停止结果不清。规则来源：[核心规则](../WORKFLOW.md)。

先读实际运行记录、相关工具结果和当前产物，再分类：

| 观察 | 下一动作 |
| --- | --- |
| 启动错误、身份或目录不匹配 | 修正入口、绑定和环境，重新取得本回合证据 |
| 正常编译、下载或持续调查 | 按预期活动节奏复核，避免重复启动 |
| 等权限、输入、依赖或主机在线 | 记录具体恢复条件，推进其他独立工作 |
| 相同错误重复且没有新证据 | 核对假设，缩小复现，改变方法或补充材料 |
| 上下文偏离 | 补原话、要求版本和已有有效成果 |
| 有证据表明模型或方法不适合 | 在授权内调整，记录依据、成本与实际通道 |
| 事件断开，停止结果未知 | 查询执行端，保留资源占用，避免冲突替代写者 |

时间长、没有代码变化本身不是卡死证据。检查点应来自任务节奏或明确标注的估计，不统一设一个全局超时。

用户暂停时先停止新增派发，再核实当前回合、子代理和工具的实际停止情况。延迟完成事件不能自动恢复暂停的任务。

每次干预记录观察、判断、动作和结果。连续失败需要新的调查与取舍；不无限重试，也不凭无依据的固定返修次数放弃原目标。
