# 拆分与并行

触发：任务包含可以独立产生有用结果的部分。规则来源：[核心规则](../WORKFLOW.md)。

## 先拆什么，再决定怎么跑

列出必要交付、各自输入、依赖、写入集合、共享资源、完成条件和集成人。需要等待的是具体依赖，不是“方案这一步还没完全结束”这样的笼统理由。

| 工作性质 | 候选方式 | 要核查什么 |
| --- | --- | --- |
| 小且明确的修改 | 主执行者直接做 | 范围和检查方法是否明确 |
| 独立调查、日志分析或检查准备 | 原生子代理或合适的既有会话 | 输入独立、返回有用、额外成本合理 |
| 可独立交付的实现 | 多会话，按需要隔离工作区 | 写入/Git 操作冲突、接口、集成人 |
| 共享核心文件或设备 | 相关步骤串行，其他工作继续 | 具体控制者和解除依赖条件 |
| 独立验收 | 独立上下文和检查方法 | 原始要求、实际受检版本和真实入口 |

同目录不同文件不自动冲突；不同分支也不自动隔离。需要不同分支、冲突写入或运行互相影响时使用适当隔离或串行。数据库、端口、设备等资源不会因新建工作区自动独立。

## 派发与收回

每个工作包给出目标和要求编号、必要材料、允许动作与写入范围、产物、验收、依赖、集成人和下一检查点。主执行者继续处理自己的非重叠工作。

检查实际执行的时间重叠及新产物，区分外层多会话和工具内部子代理。交付时核对版本、冲突和集成成本。

并行收益不抵额外调用、资源争用或集成成本时，选择更简单的安排并说明依据。没有全局固定数量，也不把开了很多 Agent 当作成绩。
