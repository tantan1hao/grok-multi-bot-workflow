# 接续已有任务

触发：同一目标继续、追加要求、阶段交接或返修。规则来源：[核心规则](../WORKFLOW.md)。

1. 从项目唯一 TODO 读取原目标、最新要求、实际主机、会话、工作区、当前控制者和最近检查点。
2. 核查执行端是否仍活动、是否已有输入排队。查询状态与追加执行分开，避免问一次进度就重跑一遍任务。
3. 用当前入口已核实的恢复或排队方式传入增量：变化、有效成果、未决问题和下一步。核对实际模型通道和权限。
4. 查看正确原生会话是否开始处理本次输入。消息已送达、启动器存活都不单独证明开始。
5. 阶段完成后，把事件、产物与要求关联，交进度维护者记录；负责人继续已授权下一节点。

用户直接找工程师修改要求时，同步原话、变化影响和证据，原任务其他要求继续有效。普通查询直接回答已有证据。

原会话不可恢复时，先保留原要求、产物版本、检查结果和未决问题，再按授权交接；记录新旧关系。无法确认旧写者停止时，不能启动会冲突的替代写者。

完成证据：正确执行身份处理了本次增量，出现可关联的事件或产物。没有发生实际执行时如实写等待原因。
