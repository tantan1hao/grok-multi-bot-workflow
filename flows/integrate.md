# 集成、验收与交付

触发：子项返回、准备交付、阶段完成或控制权交接。规则来源：[核心规则](../WORKFLOW.md)。

1. 集成人核对各项产物身份、差异、要求覆盖和自检范围，处理代码、配置、依赖、共享状态与入口接线。
2. 在集成后的同一受检版本上运行必要检查，从用户实际使用的入口走通。
3. 中大任务的关键结论由非实现者独立检查；小改动采用相称自检。检查记录说明输入、环境、版本、结果和未覆盖范围。
4. 不通过时保留有效成果，只安排受影响节点返修，优先交原实施会话继续。
5. 负责人对照本轮要求检查完成条件，提供成果入口、验证证据、偏差、假设和限制。候选工作不自动阻止本轮结项。
6. 进度维护者更新唯一 TODO 顶部“现在这件事”。负责人凭证据接续已授权下一节点，给总助必要摘要；总助协调跨项目冲突与漏接。

子任务自述完成、进程退出、测试数量多，都不能单独触发父任务完成。没有实际完成事件或已验证补查方式时，应明确接续覆盖缺口。

提交号之外还要核对未提交变化。修改输入、要求、环境或产物时，判断受影响的检查；无关提交不使所有验收作废。
